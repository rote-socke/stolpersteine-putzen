# Contract

The shared interfaces between the data script, the Worker API and the web app.
Change them only together with every side that uses them.

## Location data: `public/data/locations.json`

Generated by `npm run data` from the public KML of
<https://www.stolpersteine-stuttgart.de/stolpersteine.kml>. One entry per
address; several stones at one address share an entry.

```jsonc
{
  "generatedAt": "2026-10-28T12:00:00Z",
  "source": "https://www.stolpersteine-stuttgart.de/stolpersteine.kml",
  "locations": [
    {
      "id": "a1b2c3d4e5",            // stable: first 10 hex chars of sha1(normalized address)
      "address": "König-Karl-Str. 43",
      "lat": 48.8044,
      "lon": 9.2182,
      "district": "cannstatt",       // "cannstatt" or null
      "stones": [
        {
          "name": "Ernst Baer",
          "bioUrl": "https://www.stolpersteine-cannstatt.de/node/142", // absolute, or null
          "links": [{ "label": "Podcast", "url": "https://open.spotify.com/..." }]
        }
      ]
    }
  ]
}
```

## Cleaning state

Each location has one status:

- `open`: nobody is on it (also the status of a reservation older than 45 minutes)
- `on_the_way`: reserved by one group
- `cleaned`: done, with group and time

A group holds at most one reservation. A note is independent of the status.

## API

All bodies are JSON. Times are Unix milliseconds. Errors answer
`{ "error": "<code>", ... }` with a fitting HTTP status.

Writes need `Authorization: Bearer <groupToken>`, except creating a group and
the organizer endpoints, which need `X-Organizer-Code: <code>`. Reads need
nothing.

| Method and path | Auth | Body | Success |
|---|---|---|---|
| `GET /api/state` | none | | `{ now, groups: [{id, name, namePending}], locations: { [id]: LocationState } }`; `groups` has no deleted groups |
| `POST /api/groups` | organizer code | `{ name? }` (1–40 chars; missing or empty gives a placeholder, see "Group naming") | `201 { id, name, namePending, token }` |
| `GET /api/groups/me` | group token | | `{ id, name, namePending }` |
| `PUT /api/groups/me/name` | group token | `{ name }` (1–40 chars, trimmed) | `{ id, name, namePending: false }`; `409 name_taken`; `409 { error: "name_locked", name }` if the group is already named |
| `POST /api/locations/:id/reserve` | group token | | `{ location: LocationState }`; releases the group's previous reservation; `409 { error: "taken", groupId, groupName }` if another group holds a live reservation, `409 { error: "cleaned" }` if already cleaned |
| `POST /api/locations/:id/release` | group token | | `{ location }`; only the own reservation |
| `POST /api/locations/:id/clean` | group token | | `{ location }`; allowed from any status |
| `POST /api/locations/:id/reopen` | group token | | `{ location }`; undoes `cleaned` |
| `PUT /api/locations/:id/note` | group token | `{ text }` (max 500 chars, empty clears) | `{ location }` |

### Presence (opt-in phone positions)

A phone that switched on "Meinen Standort teilen" sends its latest position so
groups can see each other. Positions are never public: reading needs a group
token (`Authorization: Bearer`) or `X-Organizer-Code`; neither is `401`.
`deviceId` is a random id per phone (16 random bytes, base64url, kept in
`localStorage`), so the map shows one dot per phone.

| Method and path | Auth | Body | Success |
|---|---|---|---|
| `PUT /api/presence` | group token | `{ deviceId, lat, lon, accuracy }` | `204` |
| `DELETE /api/presence/:deviceId` | group token | | `204` |
| `GET /api/presence` | group token or organizer code | | `{ now, people: [{ deviceId, groupId, groupName, lat, lon, accuracy, updatedAt }] }` |

- `PUT` validates: `deviceId` 8–64 chars of `[A-Za-z0-9_-]`, `lat` in
  -90..90, `lon` in -180..180, `accuracy` a finite number >= 0 (stored capped at
  10000 m); otherwise `400 invalid`. It is an upsert; a device row of another
  group moves to the caller's group (phone switched group).
- `DELETE` only removes a row of the caller's group; otherwise a no-op, still `204`.
- Only the latest position per device is kept, no history, and positions are not
  logged. `GET` lists only rows from the last 10 minutes and of non-deleted
  groups; every `PUT` also deletes rows older than 10 minutes.
- Deleting a group and "Neuen Link" (`rotate`) delete the group's presence rows.

### Organizer endpoints

All need `X-Organizer-Code`; a wrong or missing code is `401 unauthorized`. An
unknown or deleted group id is `404 not_found`.

| Method and path | Body | Success |
|---|---|---|
| `GET /api/orga/groups` | | `{ groups: [{ id, name, namePending, createdAt, cleanedCount, reservation: { locationId, expiresAt } \| null }] }`; not deleted, in creation order; `reservation` only while live. Also the code check when entering organizer mode |
| `GET /api/orga/groups/:id/invite` | | `{ id, name, token }` |
| `POST /api/orga/groups/:id/rotate` | | `{ id, name, token }`; the old token stops working |
| `PATCH /api/orga/groups/:id` | `{ name }` (1–40 chars) | `{ id, name }`; `409 name_taken`; also sets `namePending` to false |
| `DELETE /api/orga/groups/:id` | | `204` |

Group tokens are derived: `token = base64url(HMAC-SHA256(INVITE_SECRET,
"<groupId>:<tokenVersion>"))`. The database stores only the SHA-256 of the
current token (`token_hash`). A new group has version 0. "Neuen Link" (`rotate`)
raises the version, so all earlier QR codes and links stop working. A group
from before the derivation has a random token; its first `invite` call stores
the hash of the derived token instead (one-time switch, old links stop working).

`DELETE` is a soft delete: the group's `on_the_way` reservation is removed, its
name and token stop being valid (the name can be used again), cleaned rows and
notes stay. Locations cleaned or noted by a deleted group show the group name
as `"<name> (gelöscht)"` in `groupName`.

`LocationState`, only listed for locations that have a status other than
`open` or a note:

```jsonc
{
  "status": "open" | "on_the_way" | "cleaned",
  "groupId": "g_...", "groupName": "Gruppe A", "updatedAt": 1761650000000,
  "expiresAt": 1761652700000,          // only for on_the_way
  "note": "Stein fehlt", "noteUpdatedAt": 1761650000000  // optional
}
```

Error codes: `unauthorized` (401), `forbidden` (403), `not_found` (404,
unknown location id or API path), `invalid` (400, or 405 for a wrong method),
`taken`, `cleaned`, `name_taken` (409, group name already used, compared
case-insensitively), `name_locked` (409, the group already has its final
name; carries the current `name`), `internal` (500).

Details:

- Reserving a location the group already holds restarts its 45 minutes.
- `release` and `reopen` on a location that is already open answer with its
  state instead of an error. `release` of another group's live reservation or
  of a cleaned location is `403 forbidden`.
- A note is trimmed; an all-whitespace note deletes it.
- `GET /api/state` lists groups in creation order.

## Group naming

A group created without a name gets the placeholder `Gruppe N` (lowest `N >= 1`
whose name is free, compared case-insensitively) and `namePending: true`. The
group may replace it once with `PUT /api/groups/me/name`; the update is one
conditional statement, so of two racing phones only one wins and the other gets
`409 name_locked` with the winning name. After that, only the organizer can
rename (`PATCH`). A rename by the organizer also ends the pending state, and a
group created with a name, and every group from before this feature, has
`namePending: false`. A deleted group's token is `401`, also for naming.

## Group invites

The invite link is `<origin>/#join=<groupId>.<groupToken>`. The token lives in
the fragment so it never reaches server logs. The app checks it with
`GET /api/groups/me`, stores group and token in `localStorage` and removes the
fragment from the address bar.
